# Chapter 4 编程模型

## 操作模式和状态

两种操作状态和两个模式，特权级与非特权级

操作状态：调试状态，Thumb 状态
操作模式：处理模式，线程模式

执行普通代码可在特权/非特权状态下，在什么状态具体看 CONTROL 寄存器

软件可将特权切到非特权，反之不行，必须依赖异常机制

[图 4.1 操作状态和模式]

线程模式可使用独立的影子栈指针，此时任务栈空间便和 OS 的栈空间独立

Cortex M 处理器启动后默认特权线程模式+Thumb状态

调试状态只用于调试操作，需要调试器发出暂停请求或者处理器中调试部件产生调试事件，此时可以访问/修改处理器寄存器数值

## 寄存器

主要只讲特殊寄存器即可

SP： MSP, PSP
LR
PC

栈指针 SP： 存在两个，MSP 和 PSP，默认为 MSP，在复位或者处理模式下会被处理器选择使用。而 PSP 只能用于线程模式，栈指针的选择由 CONTROL 寄存器决定

对于一般的程序来说，两个寄存器互斥，同一时间只能有一个可见

一般只有在有 OS 的情况下， PSP 才会被使用，此时 OS 内核同应用任务的栈是相互独立的，PSP 初始值未定义， MSP 初始值总是在复位流程中从存储器的第一个字取出

链接寄存器 LR：用于函数/子程序调用时返回地址的保存，执行完函数/子程序之后将 LR 装载回 PC 以继续执行

异常处理期间 LR 会被自动更新为特殊的 EXC_RETURN（异常返回）数值

程序计数器 PC：没必要介绍

msp 和 psp 使用特殊指令 mrs 和 msr 访问

一些特殊的寄存器

CONTROL 寄存器：定义栈指针选择，线程模式访问等级（特权/非特权），对于带 FPU 的 M4 处理器，还有一位用于表示当前执行代码是否使用浮点单元

CONTROL 寄存器在 M4 内核中有三个位指示这些信息： nPRIV, SPSEL, FPCA

| 位           | 功能                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| nPRIV(bit 0) | 定义线程模式中的特权等级，0：特权模式（default），1：非特权模式                         |
| SPSEL(bit 1) | 定义栈指针的选择，0：MSP（默认），1：PSP，处理模式下自动选择 MSP 并忽略任何对其的写操作 |
| FPCA         | 浮点上下文活跃，只有 M4 内核有                                                          |

复位后这个寄存器默认为零

运行在非特权等级的程序无法再切回特权访问等级，由此为一个基本的安全模型（避免不受信任的应用导致整个系统崩溃）

使用嵌入式 OS 时每次上下文切换均可重新编程该寄存器，用于满足应用不同的特权访问等级需要，nPRIV 和 SPSEL 有四种情况，其中三种比较常见

对于没用 OS 的程序，基本不需要改 CONTROL 寄存器，就用特权访问等级和 MSP 就够了

## 存储器系统

特性不管

存储器映射：
- 程序代码访问 CODE 段
- 数据访问 SRAM 段
- 外设区域
- 处理器内部控制/调试部件

可以有一些骚操作，比如把代码放 SRAM 或者数据放 CODE

所有 Cortex M 处理器的存储映射都是一样的

栈存储

需要栈指针（R13），LIFO 数据存储缓冲，PUSH/POP 指令

栈的用途：
- 需要使用寄存器进行数据处理时临时用于存储数据初始值
- 往函数/子程序的信息传递
- 存储局部变量
- 在中断等异常产生时保存处理器状态和寄存器数值

Cortex-M 采用 “满递减” 栈模型（堆栈指针指向最后压入的数据，堆栈在内存中往低地址方向增长），处理器启动后 SP 先被设置为栈存储空间最后的位置，每次 PUSH 操作都是先减小 SP 的值，再把数据存到 SP 指向的存储器位置，在操作期间，SP 指向上一次数据被存储在栈中的位置; POP 操作，SP 指向的存储器位置的数据被读出，SP 自减

两个栈指针，除 CONTROL 控制以外，在处理模式到线程模式的异常返回期间，栈指针的选择可由 EXC_RETURN 数值决定

```asm
mrs r0, msp ; 将主栈指针读入 r0
msr msp, r0 ; 将 r0 写入主栈指针
```

多数程序不需要显式访问 msp 和 psp, 这两个通常用于嵌入式 OS（切换上下文）

存储器保护单元可以忽略

## 异常和中断

异常：改变程序流的事件
其产生后，处理器暂停当前执行的任务，转而执行一段被称为异常处理的程序，执行完之后回到之前的任务

ARM 架构，中断就是异常的一种，由外设/外部输入产生，或者软件触发，对应的处理程序被称为 ISR

Cortex-M 有多个异常源

每个异常源均有自己的编号，1～15为系统异常，往下则用于中断
异常向量存储在向量表中，在异常入口流程中处理器会读取该表格以确定异常处理的起始地址
CMSIS 标准中，中断编号从 0 开始，系统异常编号为负数

复位是一种特殊的异常，从复位中退出时就会在线程模式下执行复位处理

NVIC 和 向量表不讲了

错误处理机制，所有的错误默认都会触发 HardFault （因此 FORCED 经常为 1）
UsageError，MemManageError 和 BusError 的 ISR 默认不使能， HardFault 则总是使能

## 系统控制块（SCB）

在 NVIC 中，提供控制处理器配置，错误状态信息和向量表重定位

## 复位和复位流程

复位类型有三种：上电复位，系统复位，处理器复位

复位后已经处理器开始执行程序前，处理器会从存储器中读出头两个字（MSP初始值和复位向量的值），然后赋值给 MSP 和 PC
必须要给 MSP 赋值，因为复位的那段时间内有可能触发 NMI 和 HardFault。

# Chapter 7 异常和中断

异常流程简介：

## 接受异常请求

满足如下条件即可：处理器正在运行 && 异常被使能 && 异常优先级高于当前等级 && 异常未被屏蔽

## 异常进入流程

1. 多个寄存器和返回地址被压入当前使用的栈，压栈可以使用 PSP 或者 MSP，取决于当前处理器是什么模式以及使用什么栈指针
2. 取出异常向量（异常处理/ISR 起始地址）
3. 去除待执行异常处理的指令
4. 更新多个 NVIC 寄存器和内核寄存器

根据压栈时实际使用的栈，在异常处理开始前，MSP 或 PSP 的数值会相应地被自动调整，PC 也会更新为异常处理的起始地址，LR 则会被更新为 EXC_RETURN 的特殊值（部分位保存异常流程的状态信息），该数值用于异常返回

## 执行异常处理

在执行异常处理时处理器处于处理模式，此时：
- 栈操作使用 MSP
- 运行在特权模式

若执行过程中触发了新的异常，则视其优先级决定该异常被挂起或者被执行（当前正在执行的异常先刮起），这种情况叫异常嵌套
异常处理的结尾，程序代码执行的返回会引起 EXC_RETURN 数值被加载到 PC 中，并触发异常返回机制

## 异常返回

对于 ARM Cortex-M 处理器，异常返回机制由一个特殊的地址 EXC_RETURN 触发，该数值在异常入口处产生并被存储在 LR 中，当该数值由某个允许的异常返回指令写入 PC 时就会触发异常返回流程

异常返回可由一些特定指令产生，此时触发出栈（恢复之前保存在栈中的寄存器值）

生成代码时 C 编译器会把 LR 中的 EXC_RETURN 数值当作普通返回地址处理，不过由于该机制，函数一般不会返回到 0xF0000000~0xFFFFFFFF 中，此外根据架构定义，这段地址对应的存储器本身就不能用于程序代码，因此也没什么问题

# Chapter 8 深入了解异常处理

## C 实现的异常处理

寄存器调用约定 —— AAPCS 规范

C 函数可以修改 R0~R3, R12, LR, PSR, 如果要用 R4~R11 则需要先把数据存起来（如存栈），函数调用后不需要使用的寄存器数值则不需要被保存

R4~R11 为被调用者保存寄存器，被调用的子程序/函数需要确保这些寄存器在函数结束时不会发生变化（可以在运行时变化，但执行完成之后必须恢复为初始值）

对于浮点单元也是类似的

R0~R3 为入参，R0 用于返回结果，如果是64位的则 R1 也用于返回

C 函数想用于异常处理则必须遵守 AAPCS 规范
异常入口处自动保存 R0~R3, R12, LR, PSR, 异常退出后恢复，这些都由处理器硬件控制
这样，当返回到被中断的程序时，所有寄存器的数值都会和进入中断时相同
此外和普通 C 函数调用不同，返回地址（PC）的数值不存在 LR 中（因为异常机制会在进入异常时把 EXC_RETURN 放到 LR 中，该数值在异常返回时被用到）

栈帧：

栈帧大小有 8/26 位（对于带 FPU 的 M4 内核而言），默认双字栈对齐（以保证栈指针位于异常处理的开始处）

EXC_RETURN:

处理器进入异常/ISR 时， LR 的数值会被更新为 EXC_RETURN 的数值
当利用 bx, pop 或存储器加载指令(ldr, ldm)被加载到程序寄存器中时，该数值用于触发异常返回机制

EXC_RETURN 的一些值

## 异常流程

异常进入和压栈：

在中断请求发生时，会进行压栈和取数据，压栈操作可以使用主栈（MSP）或进程栈（PSP）

然而处理模式下处理器必须使用 MSP，所有嵌套中断的压栈操作也会使用 MSP

异常返回和出栈：

异常处理结束时，入口处生成的 EXC_RETURN 的 bit1 用于确定使用什么栈指针提取栈帧

# Chapter 10 OS 支持特性

## 影子栈指针

即 MSP 和 PSP

PSP 用于任务，MSP 用于 OS 内核/中断处理

一般来说要使用进程栈需要将 OS 置于处理模式，直接编程 PSP 之后利用异常返回流程跳转到应用任务
例如当 OS 从线程模式启动时可利用 SVC 异常进入处理模式，并创建进程栈中的栈帧，且触发使用 PSP 的异常返回，当加载栈帧时应用任务就会启动

OS 需要在不同任务间切换（又称为上下文切换），通常在 PendSV 异常中执行，该异常可由 SysTick 异常触发，在上下文操作中需要：

- 将寄存器当前状态保存到当前栈中
- 保存当前 PSP 数值
- 将 PSP 设置为下一个任务的上一次的 SP 数值
- 恢复下一个任务上一次的数值
- 利用异常返回切换任务

上下文切换在 PendSV 中执行，其优先级一般设置为最低，以避免在中断过程中产生上下文切换

## SVC 异常

SVC(请求管理调用)，PendSV(可挂起的系统调用)

对于需要高可靠性的系统，应用程序可以运行在非特权模式，而有些资源可以被设置为只可在特权模式下访问（借助 MPU）

SVC 提供非特权模式下的应用程序访问被特权模式保护起来的资源的权限
应用程序本身无法直接访问这些资源，必须经过 OS 来访问，因此会更加安全

应用任务只需要知道 SVC 服务编号和 OS 服务所需参数即可访问对应资源

此外 SVC 还用于 OS 第一次初始化（图10.2）
